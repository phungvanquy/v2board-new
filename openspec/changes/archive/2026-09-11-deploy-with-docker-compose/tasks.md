## 4. Compose Orchestration

- [x] 4.1 Create `docker-compose.yml` at repo root defining services `app` (build `Dockerfile`, `entrypoint.sh`, volumes for `storage/` + `bootstrap/cache`), `nginx` (`nginx:stable-alpine`, depends on `app`, port `${APP_PORT:-8080}:80`), `db` (`mysql:8.0`, `MYSQL_DATABASE`/`MYSQL_USER`/`MYSQL_PASSWORD` from env, `healthcheck: mysqladmin ping`, volume `db_data`), `redis` (`redis:7-alpine`, optional `requirepass`, volume `redis_data`, healthcheck `redis-cli ping`), and `horizon` (same image as `app`, `command: php artisan horizon`, `depends_on` db/redis healthy, `restart: unless-stopped`), with named volumes `db_data`/`redis_data`, `env_file: [.env]`, and `depends_on: condition: service_healthy` for ordering — verified: `docker compose config` validates; `docker compose up -d` reaches `(healthy)` for db/redis/app/horizon and nginx; `docker compose ps` shows all five running. Design note 2: nginx is a `nginx` build target of the same Dockerfile (COPYing `public/` from the app stage) rather than the stock image, so assets refresh on rebuild instead of living in a never-refreshed pre-populated volume
- [x] 4.2 Add optional `webman` service gated by `profiles: ["webman"]` running `php -c cli-php.ini webman.php` (requires `pcntl`/`adapterman` already conditionally installed) — verified: `docker compose config | grep -c "webman:"` prints `0` (absent from the default graph) and `docker compose --profile webman config | grep -c "webman:"` prints `1`; `WITH_WEBMAN=true` adds `joanhey/adapterman` in the vendor stage so the profile works without an app-code change

## 5. Entrypoint and Data Initialization

- [x] 5.1 Create `.docker/entrypoint.sh` (POSIX `sh`, executable) that waits for `db`/`redis` (TCP probe loop with timeout), creates `.env` from `.env.docker.example` if missing and generates `APP_KEY` if empty (`php artisan key:generate --force`), runs `php artisan config:clear`, ensures `storage/` and `bootstrap/cache` are writable and `php artisan storage:link` is applied, then `exec "$@"` — verified: `sh -n` passes and the script runs under the image's busybox `ash`; container logs show `db (db:3306) is up`, `redis (redis:6379) is up`, `Configuration cache cleared!`, `ready: php-fpm`; an empty `.env` gets a generated `APP_KEY` (`grep ^APP_KEY= .env` shows a `base64:` value). `shellcheck` is not installed on this host, so lint is `sh -n` plus a successful busybox-ash run
- [x] 5.2 Implement idempotent first-boot DB initialization in the entrypoint: if the sentinel table is absent import `database/install.sql` (or run the non-interactive equivalent of `v2board:install` using `ADMIN_EMAIL`/`ADMIN_PASSWORD` env when provided); subsequent boots skip import — verified: first boot logs `database is empty — importing database/install.sql` + `install.sql imported` and `SHOW TABLES` returns all 28 v2 tables; a second boot logs `database schema present — skipping install.sql` and `probe@e2e.test` created between boots survives. Design note 3: detection uses `SHOW TABLES LIKE 'v2_user'` rather than the `migrations` table because V2Board does not use Laravel migrations; notes 4-6: the import runs `mysql --skip-ssl` (TLS verification error against `mysql:8.0`) with the exit code captured outside the log pipe, and the entrypoint pre-warms `config/theme/default.php` + `config:cache` so the first request is 200 instead of `500 请检查V2Board目录权限`
- [x] 5.3 Wire queue supervision: Horizon container runs `php artisan horizon` with `restart: unless-stopped` and logs to stdout — verified: `docker compose logs horizon` shows `Horizon started successfully.` plus `Processing:/Processed: App\Jobs\E2EProbe`; `docker compose restart horizon` re-launches unattended; `php artisan horizon:list` reports `Supervisors: supervisor-1, V2board` and `running`. Design notes 8-9: `APP_ENV` must stay `local` (supervisors are only defined for `local`) and jobs must target a watched queue (`->onQueue('stat')`), not `default`
